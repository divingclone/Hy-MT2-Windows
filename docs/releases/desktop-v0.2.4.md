# HyMT 0.2.4 · 优化 32 并发吞吐

默认 32 并发的 CUDA Graph 覆盖从 64 提高到 256 token，改善混合预填充与解码吞吐；模型精度、采样、KV 容量及活动序列上限不变。API、桌面和离线批量共用配置。

RTX 5090，同一正式运行库三组复测：**4,758 → 7,700 TPS（+61.8%）**，P95 **552 → 330 ms**。请求阶段显存峰值增加 **104 MiB**；首次重新编译时新旧全过程峰值均约 4.02 GiB。详细条件见仓库 `docs/LOW_CONCURRENCY_TPS.md`。

## 与官方 llama.cpp 对比

| 并发 | 部署方案 | TPS（输出 token/s） | 显存峰值增量（GiB） |
| --- | --- | ---: | ---: |
| 32 | 官方 llama.cpp + Q4_K_M / F16 KV | 1,351.39 | 5.01 |
| 32 | 本项目 vLLM + NVFP4 / INT8 KV | 7,391.52 | 3.82 |
| 256 | 官方 llama.cpp + Q4_K_M / F16 KV | 1,500.00 | 8.16 |
| 256 | 本项目 vLLM + NVFP4 / INT8 KV | 20,462.47 | 5.89 |

同一非流式 API、512 条请求，每配置三组独立进程、每组三轮热测；显存为设备全生命周期峰值减启动前基线的中位数。完整记录见 `docs/OFFICIAL_API_024.md`。

## 验证

- 工作区、跑分和发行包统一使用正式运行库，沿用 0.2.3 已验收的定制 PyTorch，并核对二进制 SHA-256。
- 32 并发性能 12,288 条、显存 4,096 条请求全部成功；受控调度 1,024 组输出逐 token 一致。
- 256 并发 1,024 条、INT4 64 条功能验证通过；84 项 Python、3 项前端、Rust 清理和真实 GPU 鉴权、流式、重启检查通过。
- 仅 RTX 5090 实卡验证；在线多进程调度不保证逐次译文一致，显存是采样峰值。原服务配置为 128 并发时没有额外图覆盖收益。

附件包含 ZIP、Tauri 更新签名、`desktop-latest.json`、`SHA256SUMS.txt` 和 `release-validation.json`。使用已有更新签名，不含 Windows Authenticode 签名。
